What Is a Regular Expression?

A regular expression, usually shortened to regex or regexp, is a compact string of characters that describes a pattern of text. Instead of searching for one exact phrase, a regex lets you describe the shape of what you're looking for — "three digits, a dash, then four digits" or "an at-sign somewhere in the middle of the word." Once you can describe shape instead of exact text, a single line of regex can validate an email field, pull every URL out of a log file, or rewrite thousands of filenames in one pass.

Regex engines exist in nearly every programming language and text editor, including JavaScript, Python, PHP, Java, Go, and tools like grep, sed, and VS Code's find-and-replace. The syntax is not identical everywhere, but the core ideas — character classes, quantifiers, groups, anchors — are shared across almost all of them, which is why learning regex once pays off across your entire toolchain.

How Regular Expressions Work

Under the hood, a regex is compiled into a small state machine that walks through your input text character by character, trying to find a position where the pattern matches. Most engines, including JavaScript's, use a backtracking strategy: when a part of the pattern fails to match, the engine backs up and tries a different path — a different length for a quantifier, a different branch of an alternation — before giving up entirely. This is why an overly complex pattern can sometimes be slow: the engine may explore many possible paths before it finds a match or confirms there isn't one.

In this tester, every keystroke re-compiles your pattern with JavaScript's native RegExp object and re-runs it against your test string, so what you see is exactly what String.prototype.match, replace, or split would do in real code.

Regex Syntax Explained

A regex is built from two kinds of characters: literals, which match themselves exactly, and metacharacters, which carry special meaning. The metacharacters in most flavors are:

. * + ? ^ $ { } [ ] ( ) | \

Any of these characters used outside of their special role must be escaped with a backslash — for example, to match a literal period in a domain name you write \. rather than ., which would otherwise match any character.

Character Classes & Metacharacters

A character class matches one character from a defined set. Square brackets define a custom class: [aeiou] matches any single vowel, and [^0-9] matches anything that is not a digit. Ranges like a-z or 0-9 can be combined inside brackets: [a-zA-Z0-9_] matches any letter, digit, or underscore — which is exactly what the shorthand \w already means.

Anchors

Anchors don't match characters — they match positions. ^ matches the start of the string (or the start of each line with the m flag), and $ matches the end. \b matches a word boundary, the invisible point between a word character and a non-word character, which is exactly what you want when searching for the whole word "cat" without also matching "category."

Groups: Capturing, Named & Non-Capturing

Parentheses create a capture group, which both groups part of the pattern together (so a quantifier can apply to the whole group) and remembers the text it matched, so you can reuse it in a replacement string as $1, $2, and so on. If you only need the grouping behavior and don't want the overhead of capturing, use a non-capturing group: (?:abc).

Named groups, written (?<year>\d{4}), let you reference the captured text by name instead of by index — both in JavaScript's match.groups.year and in a replacement string as $<year>, which makes complex patterns dramatically easier to read and maintain.

A backreference like \1 matches whatever the first group already matched earlier in the same pattern — useful for finding repeated words such as \b(\w+)\s+\1\b.

Lookaheads & Lookbehinds

Lookarounds check for a condition without consuming any characters, which makes them ideal for validation rules like password strength.

Lookaround types
SyntaxNameMatches when…
(?=abc)Positive lookaheadfollowed by "abc"
(?!abc)Negative lookaheadnot followed by "abc"
(?<=abc)Positive lookbehindpreceded by "abc"
(?<!abc)Negative lookbehindnot preceded by "abc"

For example, a strong-password check like ^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$ uses three lookaheads to require a lowercase letter, an uppercase letter, and a digit anywhere in a string of at least 8 characters, without those lookaheads consuming any of the text themselves.

Quantifiers & Greedy vs. Lazy Matching

Quantifiers control how many times the preceding token can repeat: * (0+), + (1+), ? (0 or 1), and {n,m} for a custom range. By default quantifiers are greedy — they consume as much text as possible, then backtrack if needed. Appending ? makes a quantifier lazy, matching as little as possible instead. The difference is easiest to see on HTML-like text: against <b>bold</b>, the greedy pattern <.+> matches the entire string from the first < to the last >, while the lazy pattern <.+?> stops at the very first >, matching only <b>.

Alternation & Escaping

Alternation, the pipe character |, works like a logical OR: cat|dog matches either word. It has low precedence, so it's usually wrapped in a group: gr(a|e)y matches "gray" or "grey" without also matching a bare "a" or "e" elsewhere. Escaping with a backslash turns off a metacharacter's special meaning, so \$19\.99 matches the literal text "$19.99" instead of "end of string, any character, 99".

Regex in JavaScript, Python & PHP

The underlying syntax is nearly the same across languages, but the calling convention differs. In JavaScript, patterns are literals or RegExp objects: text.match(/\d+/g). In Python, the re module compiles a pattern first: re.findall(r"\d+", text), and raw strings (the r prefix) are used to avoid double-escaping backslashes. In PHP, the PCRE functions require delimiters around the pattern: preg_match_all('/\d+/', $text, $matches). Named groups, lookarounds, and most quantifiers behave identically across all three.

Best Practices, Mistakes & Performance

  • Anchor your pattern with ^ and $ when validating a whole field, or a partial match can slip through.
  • Prefer specific classes over .* — a broad, greedy wildcard is the most common cause of both incorrect matches and slow patterns.
  • Avoid nested quantifiers like (a+)+, a classic cause of "catastrophic backtracking" that can freeze a program on certain inputs.
  • Use non-capturing groups (?:...) when you don't need the captured value, to keep replacement indices predictable.
  • Test edge cases: empty strings, extra whitespace, unicode characters, and unexpectedly long input.
  • Never build a full email or URL validator by hand for security-critical checks — combine regex with proper parsing libraries when the stakes are high.

Regex Checklist

  • ☑ Does the pattern need ^/$ anchors?
  • ☑ Are all literal special characters escaped?
  • ☑ Greedy or lazy — which one actually matches your intent?
  • ☑ Do you need the g flag to find every match, not just the first?
  • ☑ Have you tested against empty input and the longest realistic input?
  • ☑ Could nested quantifiers cause catastrophic backtracking?

Frequently Asked Questions

What is a regular expression?

A regular expression is a pattern made of literal characters and metacharacters that a regex engine uses to match, validate, find, or replace text.

Is this regex tester free to use?

Yes — it's completely free, requires no account, and runs entirely in your browser.

Does this tool send my data to a server?

No. Matching happens locally using your browser's built-in RegExp engine, so your text never leaves your device.

What is the difference between greedy and lazy matching?

Greedy quantifiers match as much text as possible before backtracking; lazy quantifiers (written with a trailing ?) match as little as possible.

Why is my regex not matching anything?

Common causes include a missing g flag when you expect multiple matches, an unescaped special character, or case sensitivity — try enabling the i flag.
